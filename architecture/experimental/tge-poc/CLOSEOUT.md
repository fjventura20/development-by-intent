## 4. Adversarial composition-attack result (Case 6)

The case 6 adversarial variant produced a quote with PCRs derived from the attacker's runtime fingerprint and a quote-referenced signing-key handle pointing to the attacker's freshly minted key. The runtime_fingerprint field in the turn was spoofed to match the legitimate runtime's. The verifier caught this on the *first* quote-handle check (before the per-turn signature check), producing `GX_RUNTIME_REPLACED` with reason `runtime_replaced`. The composition attack (valid quote + substituted runtime key) did NOT pass.

This validates the v0.2.1 §B.3.3 PCR-binding closure. Without it, the verifier would have produced `GX_ATTESTATION_INVALID` (signature verification failure) rather than the precise `GX_RUNTIME_REPLACED` — and worse, with a less strict verifier, the attack could pass.

### Real
- Canonicalization (with 7 normative test vectors; signer/verifier byte-identical)
- Ed25519 sign/verify
- Signature-key continuity checking (cross-binding of quote's signing_key_handle to receipt's runtime_pubkey)
- Freshness window enforcement (verifier-side)
- Roster verification under RTA signature
- Charter SHA-256 match
- Provenance distinction (envelope vs inline)
- Collocation detection (in-process flag)
- PCR-derived-from-fingerprint binding (closes composition attack)

- "swtpm" attestation: Python module produces fixture-shape quotes; not a real swtpm daemon
- "manufacturer root": fixture Ed25519 key
- "TPM AK": fixture Ed25519 key
- "RTA key": fixture Ed25519 key
- "issuer key": fixture Ed25519 key
- Runtime binary "PCR measurement": computed deterministically from `runtime_id` string (hashlib.sha256 of `"runtime-binary:{runtime_id}"`)
- Participant / model: zero invocations; the runtime is a deterministic stub

### Not tested (out of PoC scope)

- Host compromise resistance
- Production RTA service
- Transparency log
- Live revocation
- Cross-arm contamination
- Behavioral testing of any AI model

## 6. Deviations from frozen PoC design

- LOC is 1647, above the 600-820 target. Cause: cases.py inlines setup per-case rather than sharing fixtures; verifier.py inlines error-path verbosity. Both can be condensed without changing behavior; deferred unless PI requests further minimization.
