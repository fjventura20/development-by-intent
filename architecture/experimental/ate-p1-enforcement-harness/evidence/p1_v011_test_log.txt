Notes on design judgments:
  - Used 16 subprocesses for T5 cross-process boundary (per v0.1.1
    §C4). Each subprocess is a real OS process; the requester has no
    DB handle, no audit key, no resource credential. The privilege
    boundary is enforced by the executor's sole possession of those
    materials (verified in T2 by inspection).
  - T6 (transaction rollback) used a deterministic barrier that
    raises an exception between nonce reservation and audit append,
    exercising the C1 rollback property.
  - T9 tampered the audit chain by directly UPDATEing the audit_records
    row's operation field; the worker's startup integrity check
    re-verifies the MAC chain and detects the inconsistency.
  - The empty-audit-chain case (verified in startup before any
    execution) is treated as a valid empty chain. The schema initializer
    inserts an anchor row with empty digest/empty MAC; verify_audit_chain
    accepts this when records=[].
  - Resource credential model: each resource_id has a 32-byte random
    credential held only by the executor (in config.resource_credentials).
    The mutation path requires presenting this credential. The
    requester cannot reconstruct it. (T1 + T2 verify this.)
  - Revocation model: revocations are stored in the revocations table
    inside the same authority DB. The executor reads revocations
    inside the transaction (E5) and after the barrier (re-verification).
    A revocation committed before the transaction begins is observed
    at E5 and denies execution.
  - Schema choice: protected_resources, nonces, revocations, audit_records,
    audit_anchor, decision_signatures, executor_state all in one SQLite
    file. WAL mode + BEGIN IMMEDIATE provides atomicity.
