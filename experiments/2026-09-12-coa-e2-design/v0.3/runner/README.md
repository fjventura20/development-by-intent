# COA-E2 v0.3 deterministic runner

The runner is executable code, not a freeze-time placeholder. It has four roles:

- `run_pilot.py`: validates runtime manifest, requires six pre-existing isolated profiles and six unique runtime nonces, executes the counterbalanced six-session plan, initializes once with `--oneshot`, then uses `--resume` for all later turns, captures CLI stdout/stderr/return code, and globally stops on failure.
- `audit_after_turn.py`: read-only SessionDB audit; checks expected count, exactly paired user/assistant rows, missing assistant, unexpected tool/intermediate rows, returned session ID, parent fork, raw CLI hashes, and MEMORY/USER hashes.
- `classify_response.py`: deterministic action-code parser returning `VALID_A/B/C`, `AMBIGUOUS`, or `UNSCORABLE`.
- `aggregate_pilot.py`: aggregates session records only; it does not score behavior.
- `verify_manifest.py`: verifies repository-root-relative hashes before Hermes is invoked.
- `generate_nonces.py`: generates six keyed nonces, but must not be run until a separate PI-approved freeze.

## Execution contract

1. The runner receives an externally sealed runtime manifest containing six nonce values and hashes for every controlling file except the manifest itself.
2. `verify_manifest.py` must pass before `run_pilot.py` invokes Hermes.
3. The runner requires `--execute`; `--dry-run` only validates manifest shape, six nonce keys, uniqueness, six-profile counterbalanced order, and turn counts. It never invokes Hermes.
4. No profile is created by the runner. Profiles must be newly created and blanked by the separately authorized setup step.
5. Initialization uses `--oneshot --pass-session-id` once per session. Qualification and scored turns use `--resume <initial-session-id> --pass-session-id`.
6. No digest or nonce appears in a recall prompt.
7. Every audit failure is a global STOP. No partial continuation, resume-from-N, or rerun is performed by the runner.
8. Compression, summarization, or a child-session fork is a global STOP.

## Runtime manifest

`runtime-manifest-DRAFT.json` is a design template only. Final nonces and final hashes are not generated by this draft. At freeze time, a separate runtime manifest is sealed with six nonces keyed `coa-s1` through `coa-s3` and `control-s1` through `control-s3`; its external SHA-256 is recorded in the freeze record. The manifest is deliberately not self-referential.

## Known P1 limitation

The runner records the exact application-layer initialization/task prompt bytes and the raw CLI output. Unless Hermes exposes the provider-bound serialized request, the runner must classify P1 as `P1_APPLICATION_LAYER_PASS`, not `P1_FULL_PASS`. It must never upgrade that claim automatically.
