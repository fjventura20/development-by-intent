## Status: PROPOSED 2026-08-27, awaiting Frank authorization

## Problem

RO Exp 001 (BP-RO-ARTIFACT-ONLY-CLAUDE-001) ran the R turn successfully from
`~/devProjectsU/development-by-intent/experiments/2026-08-27-receipt-organizer-
artifact-only-claude-001/` (cwd deep in the experiment directory). All three

Subsequent `--resume $SESSION_ID` calls for T1-T5 + G all returned

  The session DID receive the resume calls — evidence is in the file sizes and

- **AB 006**: 1 session jsonl on disk (83,033 bytes, **42 lines**) in the same

- **RO Exp 001**: 1 session jsonl on disk (31,087 bytes, **10 lines**) in the

  subdirectory itself. Disposition: **BLOCKED — environment-state-loss**.
  Resume calls all failed with "No conversation found".

## Root cause

The Claude Code `--resume` lookup is keyed by cwd in a way that FAILS when the
target runs from a long-path cwd with specific patterns (deep experiment
subdirectories under `~/devProjectsU/development-by-intent/experiments/...`),
but SUCCEEDS when the target runs from `/tmp/<short-name>/...`.

Reproduced cleanly:
- From `/tmp/ro-retry-from-tmp/`: T1 succeeded, T2 `--resume` succeeded with
  a continuation response ("I'm ready to help..."), session file on disk at
  `~/.claude/projects/-tmp-ro-retry-from-tmp/<uuid>.jsonl`.
- From `~/devProjectsU/development-by-intent/experiments/2026-08-27-
  receipt-organizer-artifact-only-claude-001/`: T1 succeeded, T2 `--resume`
  returned `No conversation found`.

This is a host-environment bug in Claude Code 2.1.170, not a behavioral
defect in the reconstructed application.

## v0.3 amendment

Add a session-resume pre-flight check to the R turn workflow. After the R
turn successfully produces the READY line:

1. **Step 1 — verify cwd mapping.** Confirm the cwd the target ran from
   matches a known-good cwd-keyed path pattern. If the experiment cwd is
   `~/devProjectsU/development-by-intent/experiments/<exp-id>/`, the target
   should be re-launched from `/tmp/portability-<exp-id>/` instead, with the
   operator scratch files (prompt-r.txt, prompt-tN.txt, etc.) symlinked or
   copied into `/tmp/portability-<exp-id>/`.

2. **Step 2 — resume smoke test.** Immediately after the R turn, attempt one
   `--resume $SESSION_ID` call with a benign message ("ping"). If the response
   is a continuation (rather than a fresh-start reply), proceed to tests. If it
   fails with `No conversation found`, the cwd mapping is wrong; restart the
   R turn from `/tmp/portability-<exp-id>/`.

3. **Step 3 — only then run tests.** No test should be initiated until the
   resume smoke test passes.
